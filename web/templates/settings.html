Settings

These apply to every monitored domain and take effect from the next scan. No restart is needed.

Organisation

Scanning schedule

Alerting

Alerts are only ever sent for changes: new subdomains, new IP addresses or DNS records, newly logged certificates, and new findings.

Active checks

Off by default. When on, the agent connects to your own web servers during each scan: it reads their TLS certificates, requests the home page and a few well-known files, and checks cloud storage that your DNS names point to. It only reads (GET requests and TLS handshakes), never to private or internal addresses, and by default only to addresses inside the networks you declared as yours. Only switch this on for systems you are allowed to test.

Email (SMTP)

Scheduled report email

The report lists every domain, all open findings and everything that changed in the period. It is separate from change alerts.

Data sources

All free; only AlienVault OTX needs a (free) API key. The agent only queries these public services and public DNS resolvers; it never sends traffic to your domains.

A domain's baseline is marked complete only when a Certificate Transparency source (crt.sh or CertSpotter) answered, because those are the most complete record of names.

Exposure intelligence and optional API keys

These services tell you what the internet already sees on your addresses: open ports, known vulnerabilities and registration dates. They are looked up by IP address (and, for Shodan DNS and VirusTotal, by domain name), so the addresses you monitor are shared with each service you enable. The agent never scans or connects to your hosts itself.

Shodan (API key)

Censys (Platform API)

VirusTotal (API key)

Check that a key works on the System health page after saving. Findings from these sources are based on third-party scan data that can be days old and are matched from banners, so confirm before acting.

Wider discovery

These look beyond the names you listed. They use DNS lookups and the public certificate logs only; nothing connects to anyone’s servers.

Threat intelligence off by default

These watch for threats outside your own attack surface: other people’s domains, public code and breaches. They are leads for a threat-intelligence team rather than exposures you can fix, and they are noisier, so they are off unless you switch them on. Switching one off closes its open findings (risks you accepted are kept).

Restoring

Restoring replaces everything, so it is done with the agent stopped: easm-agent -restore backup.zip (add -force to replace an existing database; the old one is kept alongside). If the backup does not hold the key file, put your saved easm.key into the data folder first.
